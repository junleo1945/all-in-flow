# All-in-Flow 功能总结与演示检查清单

> 整理日期：2026-10-22（基于 main `3b36050`）。依据是代码、测试和一次真实浏览器冒烟，不是设计文档里的计划。
> 设计细节见 [design.md](design.md)；本文只回答「现在能做什么、演示时哪些会掉链子」。

## 一句话

用户和 AI 顾问聊日常工作 → AI 记下画像和痛点并排序 → 生成可视化流程图（画布）→ 导出成一段提示词、一个 Agent Skill，或分享给同事。

## 一、功能清单

### 1. 登录与账号
- 用公司 ERP 账号登录（浏览器只拿 `aif_sid`，每 5 分钟向 ERP 复核账号状态）；登录限流；可退出。
- 每日 token 配额与用量条（顶栏显示）；管理员可调 `GET /api/admin/usage` 看全站用量（**只有接口，没有页面**）。
- 中英文界面，窄屏自适应。

### 2. 访谈（核心）
- 访谈 Agent 按阶段推进：角色 → 工作清单 → 挖痛点 → 排序 → 提方案 → 生成。
- 记录：岗位画像、工作项（频率、单次耗时档位）、痛点（痛苦程度、可自动化程度、依据）；痛点优先级 = 频率 × 耗时 × 痛苦 × 可自动化，耗时说不准时按默认值估算并标「未量化」。
- 选择题、2~3 个候选方案卡片、「直接生成工作流 / 换一个痛点 / 这一步不对」快捷回复；用户说「够了，出吧」进入快速模式不再追问。
- 单轮对话 SSE 流式输出；会话持久化，刷新、重启服务后可从中断处继续；单会话 80 轮上限。
- 上传图片辅助访谈（千问识别）：配置 `VISION_MODEL_ID` 后启用；格式/内容校验、去 EXIF、缩放、每日上限；前端有粘贴、拖拽上传（本次未在浏览器里验证，需要先配 `VISION_MODEL_ID`）。

### 3. 工作流与画布
- 生成：大模型输出 Workflow IR v2（JSON），服务端校验失败会把错误回喂模型，最多重试 3 次。
- IR 表达：触发（手动/定时/事件）、输入、步骤（脚本/AI/人工三种执行方式）、判断分支、循环、合并；步骤可带动作（HTTP / 大模型 / 转换 / 代码 / 人工表单）。
- 画布（Excalidraw 手绘风）：颜色区分「脚本执行 / AI 执行 / 需要人工」、小地图、版本切换（v1、v2…）、「工作画像」页签。
- 版本管理：保存为新版本，旧版本不变；旧的 v1 数据读取时自动迁移为 v2。

### 4. 导出（导出菜单共 7 项）
| 项 | 说明 | 依赖 |
|---|---|---|
| PNG / SVG / Mermaid / Excalidraw | 浏览器内完成，所见即所得 | 无 |
| 对话提示词 | 粘贴到 ChatGPT/豆包等聊天窗口，AI 带着用户一步步完成；完整版 + 精简版（2000 字内，可放智能体设定）；导出前可补「判断标准 / 模板」缺口并存为新版本 | 无 |
| Agent Skill | zip：`SKILL.md` + 参考资料 + 脚本 + 安装说明；有模型时由模型撰写并校验，没有模型自动回退到基础版并提示；同一版本、同样选项再导出直接取上次结果（弹窗里可「重新生成」），不重复花 token | 模型密钥（可选） |
| n8n 工作流 | 先在头像菜单「授权管理」添加 n8n MCP，再分析流程图、匹配节点、校验后给出可粘贴的 JSON | `AUTH_SECRET_KEY` + 可访问的 n8n MCP |
- 「人工流程（process）」不能导出成 Skill（会明确拒绝），但可以导出成对话提示词。

### 5. 分享
- 创建分享链接：锁定某个版本或始终显示最新；有效期 7 天 / 30 天 / 永久；可选同时带痛点摘要；可撤销（撤销、过期、会话删除统一返回 410）。
- 分享页只读画布，同事需登录；可「复制到我的工作台」（互相独立）。
- 公开分享（无需登录）默认关闭，需管理员开 `SHARE_PUBLIC_ENABLED`。

### 6. 本地 Skill + 平台 MCP（`/skill` 页）
- 下载访谈 Skill，装进本地 Claude Code / Codex 后不打开网站也能访谈。
- 网页生成个人访问令牌（最多 5 个、有效期可选、可撤销，明文只显示一次，库里只存摘要）。
- 平台 MCP 端点 `POST /api/mcp`（Bearer 令牌）：`validate_workflow`、`import_workflow`（新建 / 带 workflowId 存新版本，返回流程图链接）。
- 适合习惯用自己本地 Agent / 模型访谈的用户：在本地聊完，把工作流带回平台。

### 四个演示工作流
| 名称 | 覆盖的结构 |
|---|---|
| 销售周报自动汇总 | 定时触发、HTTP 取数、代码筛选、条件分支、人工确认、大模型成文 |
| 客户反馈分诊与回复 | 事件触发、循环（内含分支）、大模型分类与起草、人工确认 |
| 报销单核对流程 | 纯人工流程（process）、大模型判断、分支汇合 |
| 晨间邮件摘要 | 前半段是人的行为、后半段可自动化（适合讲「切段」） |

### 测试没有覆盖的（诚实说明）
- **真实模型**：全链路测试用假模型脚本化访谈，访谈质量、IR 生成质量、Skill 撰写质量、n8n 导出质量**没有**在本次验证。评测要花钱并写库，需单独授权。
- **真实 ERP 登录**：用的是仓库自带的假 ERP。
- **真实 n8n**：当前 n8n MCP 连接返回 401（凭证需要更新），n8n 导出的端到端本次没有跑。
- **Docker 部署形态、nginx 反向代理**：未验证，浏览器冒烟用的是本地 `vite preview`。
- **并发与长时间运行**：单实例内存里的登录限流、会话注册表，多副本部署前需要换 Redis/数据库。

## 三、演示风险与注意事项

按「会不会当场出丑」排序：

1. **n8n 导出默认不可用**：`.env` 没有 `AUTH_SECRET_KEY` 时，弹窗显示「缺少 AUTH_SECRET_KEY 配置」。想演示必须先配（`openssl rand -hex 32`），再在「授权管理」添加一个**能连通**的 n8n MCP；目前 n8n MCP 返回 401。不演示就别点。
2. **（已修复）开发模式下 Agent Skill 导出曾卡在「分析流程图」**：原因是 `React.StrictMode` 在开发模式下先卸载再挂载弹窗，第一次请求被取消，而 `started` 标记阻止了重试。已在 `SkillExportDialog` 卸载时重置标记，并加了 StrictMode 回归测试；开发模式和生产构建都已在浏览器里验证。
3. **Skill 里的 HTTP 步骤只能写成文字说明**：导出时会提示「普通 HTTP 请求尚未支持生成脚本」，属于已知限制，演示时可以主动讲。
4. **循环节点在画布上是一个方框**：子流程不展开；「客户反馈分诊」演示时只能口头讲循环内部。
5. **手机宽度下小地图和图例会盖住流程图的一部分**：功能可用，只是排版挤。演示用桌面浏览器。
6. **没有模型密钥时**：Agent Skill 导出自动回退到基础版并有提示，不会报错；但**访谈本身需要真实模型**，演示前必须确认 `DEEPSEEK_API_KEY`、代理地址、模型 ID 可用。
7. **管理员用量**只有接口、没有页面；画像里工作清单和痛点内容还不能手动编辑（只能改评分）。
8. **令牌的 ERP 复核、过期令牌定时清理**没接：离职员工的令牌到期前仍可导入工作流（不能读数据）。

## 四、演示前 5 分钟自检

```bash
# 1. 服务端、前端能起来（生产构建）
pnpm --filter @aif/web build

# 2. 对着要演示的环境跑冒烟脚本（会在该账号下新建 4 个工作流，令牌跑完自动撤销）
BASE_URL=<演示地址> DEMO_USERNAME=<账号> DEMO_PASSWORD=<密码> \
  pnpm --filter @aif/server exec tsx scripts/demo-smoke.ts

# 3. 全量自动化测试（必须指向 *_test 库）
DATABASE_URL=postgres://aif:aif@localhost:<端口>/all_in_flow_test pnpm -r test
```

注意：`pnpm test:db` 里写死的端口是 5433；在这台机器上 5433 被别的项目的数据库占用，all-in-flow 的库在 5436，请按实际端口改 `DATABASE_URL`。
